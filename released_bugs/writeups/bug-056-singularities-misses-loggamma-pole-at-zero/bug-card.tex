\section*{Bug 56: Singularities misses loggamma pole at zero}

\begin{counterexamplebox}
\textbf{Task.} Find the singularities of \(\operatorname{loggamma}(x)\) over the
complex domain.
\[
    \operatorname{singularities}(\operatorname{loggamma}(x), x, \mathbb{C})
\]

\medskip
\textbf{SymPy's answer.}
\[
    \operatorname{singularities}(\operatorname{loggamma}(x), x, \mathbb{C})
    = \varnothing
\]

\medskip
\textbf{Correct answer.} The singularity set must contain \(0\); more generally
it contains the nonpositive integers \(\{0,-1,-2,\ldots\}\).

\medskip
\textbf{Explanation.} \(\operatorname{loggamma}(0)\) evaluates to \(\infty\),
and the recorded right-hand limit satisfies
\(\lim_{x\to 0^+}\operatorname{loggamma}(x)=\infty\). Thus \(x=0\) is an
actual pole inherited from \(\Gamma(x)\), not a removable point or an equivalent
empty-set representation.

\medskip
\textbf{Likely root cause.} The diagnosis traces the call to
\texttt{sympy/calculus/singularities.py}, where \texttt{singularities} scans
only selected structural patterns such as \texttt{Pow} and \texttt{log} atoms;
\texttt{loggamma(x)} is not rewritten to \texttt{log(gamma(x))} and has no
special branch. This is a new failure mode with no public precedent.

\medskip
\textbf{Artifact (GitHub).} \bugbundle{bug-056-singularities-misses-loggamma-pole-at-zero}
\end{counterexamplebox}
