\section{Bug 58: Left Limit of elliptic\_k(x) at 1 Returns zoo}

\subsection{Minimal Reproducer}

\medskip

\begin{lstlisting}[style=bugpython]
import mpmath as mp
from sympy import elliptic_k, limit, symbols

x = symbols("x")
print("sympy_limit =", limit(elliptic_k(x), x, 1, dir="-"))

mp.mp.dps = 50
print("mpmath_ellipk_1_minus_1e_12 =",
      mp.ellipk(1 - mp.mpf("1e-12")))
\end{lstlisting}

\subsection{Observed Behavior}

\medskip

\begin{lstlisting}[style=bugpython]
sympy_limit = zoo
mpmath_ellipk_1_minus_1e_12 = 15.201804919087715174172185985894590732575028945707
\end{lstlisting}

SymPy returns \(\mathrm{zoo}\), the unsigned complex infinity, for a real one-sided limit. The nearby high-precision numerical value is finite but already large and positive, matching the expected positive real divergence as the parameter approaches \(1\) from below.

\subsection{Expected Behavior}

The mathematically correct result is
\[
\lim_{x \to 1^-} \operatorname{elliptic\_k}(x)=+\infty,
\]
so SymPy should return \(\infty\), represented by \texttt{oo}, rather than \(\mathrm{zoo}\).

\subsection{Mathematical Explanation}

SymPy's \(\operatorname{elliptic\_k}(m)\) is the complete elliptic integral of the first kind,
\[
K(m)=\int_0^{\pi/2}\frac{d\theta}{\sqrt{1-m\sin^2\theta}}.
\]
For real \(0<m<1\), the integrand is positive. As \(m\to 1^-\), the singularity develops at \(\theta=\pi/2\), and the standard endpoint expansion has logarithmic leading behavior
\[
K(m) = -\frac{1}{2}\log(1-m) + O(1).
\]
Since \(1-m\to 0^+\), \(\log(1-m)\to -\infty\), hence this leading term tends to \(+\infty\). The result \(\mathrm{zoo}\) is therefore not an equivalent representation of the one-sided real limit: it loses the real direction and sign of the divergence.

\subsection{Source-Level Diagnosis}

The diagnosis locates the relevant implementation in:
\begin{center}
\nolinkurl{sympy/functions/special/elliptic_integrals.py}
\end{center}
It identifies the \texttt{\_eval\_nseries} method of \texttt{elliptic\_k} around lines 82--84. The public call enters \texttt{Limit.doit} in \nolinkurl{sympy/series/limits.py}, proceeds through \texttt{gruntz} in \nolinkurl{sympy/series/gruntz.py}, and asks for a leading expansion after rewriting the left approach as a small positive dummy. For the representative case, the traced path is
\[
\begin{aligned}
\operatorname{elliptic\_k}(1-w)
&\longrightarrow
{}_2F_1\!\left(\frac12,\frac12;1;1-w\right),
\end{aligned}
\]
where the hypergeometric series routine returns \texttt{nan}. The elliptic function's local series method then also returns \texttt{nan}, after which the limit machinery reports \(\mathrm{zoo}\).

The problematic rule identified by the diagnosis is that the elliptic integral delegates its local series entirely to a hypergeometric rewrite:

\begin{lstlisting}[style=bugpython]
return hyperexpand(self.rewrite(hyper)._eval_nseries(x, n=n, logx=logx))
\end{lstlisting}

For \(m=1-w\) with \(w\to0^+\), the needed leading term is logarithmic and real-positive in the limit. The delegated hypergeometric \texttt{nseries} path appears not to encode this branch-point expansion, so the one-sided sign information is lost. The exact-value table returning \texttt{S.ComplexInfinity} at \(m=1\) is suitable for the singular point itself, but it is not enough to determine the directional real limit. A plausible fix direction, supported by the diagnosis, is to add a branch-aware leading term or series for \(\operatorname{elliptic\_k}\) near \(m=1\), at minimum recognizing \(m=1-w\) with \(w\) positive and returning the logarithmic leading behavior.

\subsection{Additional Failing Instances}

The independent verification checks a shifted family
\[
\lim_{x\to (a+1)^-} \operatorname{elliptic\_k}(x-a)
\]
for \(a=0,1,2,3,4,5\). In every case, the internal parameter \(m=x-a\) approaches \(1\) from the left, so the same logarithmic positive divergence applies. The recorded SymPy behavior is \(\mathrm{zoo}\) for each shifted instance, while the expected result is \(\infty\).

\subsection{Related Issues Assessment}

The bug-finding harness performed a best-effort deduplication check and classified this as a new instance of a known failure mode. The closest public match reported was SymPy issue \#27058, another \(\operatorname{elliptic\_k}\) limit problem involving a branch cut approached from imaginary directions at parameter \(2\). The report also notes issue \#26250 and pull request \#26264, which concern related elliptic or hypergeometric limit behavior. Those items indicate that the broader elliptic-integral limit and series family is known, but the available evidence did not identify a clear duplicate for the specific real endpoint case \(\lim_{x\to1^-}\operatorname{elliptic\_k}(x)\). This exact reproducible case remains individually actionable and suitable for a targeted regression test.

\subsection{Proposed SymPy Regression Test}

\medskip

\begin{lstlisting}[style=bugpython]
import pytest

from sympy import elliptic_k, limit, oo, symbols


@pytest.mark.parametrize("a", [0, 1, 2, 3, 4, 5])
def test_left_limit_elliptic_k_at_one_is_positive_infinity(a):
    x = symbols("x")
    assert limit(elliptic_k(x - a), x, a + 1, dir="-") == oo
\end{lstlisting}
