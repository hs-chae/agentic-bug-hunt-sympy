\section*{Bug 22: solveset returns 1 for acos(x) = 2*pi}

\begin{counterexamplebox}
\textbf{Task.} Solve the principal inverse-cosine equation over the complex domain.
\[
  \operatorname{solveset}(\operatorname{Eq}(\operatorname{acos}(x), 2\pi), x, \mathbb{C})
\]

\medskip
\textbf{SymPy's answer.}
\[
  \operatorname{solveset}(\operatorname{Eq}(\operatorname{acos}(x), 2\pi), x, \mathbb{C}) = \{1\}.
\]

\medskip
\textbf{Correct answer.}
\[
  \varnothing
\]

\medskip
\textbf{Explanation.} Substituting SymPy's returned value gives
\(\operatorname{acos}(1) - 2\pi = -2\pi\), so \(1\) is not a solution.  The error comes from
treating \(\cos\) as a globally valid inverse of the principal branch
\(\operatorname{acos}\), even though \(\operatorname{acos}(\cos(2\pi)) = 0\), not \(2\pi\).

\medskip
\textbf{Likely root cause.} The diagnosis points to
\(\texttt{sympy/solvers/solveset.py:\_invert\_complex}\), where the generic
inverse-function branch applies \(\texttt{acos(x).inverse() == cos}\) without a
principal-range condition and later checks only definedness.  This is a new
instance of a known failure mode.

\medskip
\textbf{Artifact (GitHub).} \bugbundle{bug-022-solveset-returns-1-for-acos-x-2-pi}
\end{counterexamplebox}
