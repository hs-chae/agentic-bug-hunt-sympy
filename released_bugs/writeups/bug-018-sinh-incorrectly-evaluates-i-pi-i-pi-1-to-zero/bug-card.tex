\section*{Bug 18: sinh incorrectly evaluates \texorpdfstring{$I\pi+I(\pi-1)$}{I*pi + I*(pi - 1)} to zero}

\begin{counterexamplebox}
\textbf{Task.} Evaluate a hyperbolic sine at a split imaginary-period argument.
\[
\sinh(I\pi + I(\pi-1))
\]

\medskip
\textbf{SymPy's answer.}
\[
\sinh(I\pi + I(\pi-1)) = 0.
\]

\medskip
\textbf{Correct answer.}
\[
\sinh(I\pi + I(\pi-1)) = -I\sin(1).
\]

\medskip
\textbf{Explanation.} The argument satisfies
\(I\pi+I(\pi-1)=I(2\pi-1)\), and \(\sinh(It)=I\sin(t)\). Hence the value is
\(I\sin(2\pi-1)=-I\sin(1)\), not zero.

\medskip
\textbf{Likely root cause.} The diagnosis identifies
\texttt{\_peeloff\_pi} in \nolinkurl{sympy/functions/elementary/trigonometric.py}
as peeling the \(\pi\)-coefficient from the nested addend \(\pi-1\) while
dropping the non-\(\pi\) remainder. The deduplication assessment classifies this
as a new instance of a known failure mode.

\medskip
\textbf{Artifact (GitHub).} \bugbundle{bug-018-sinh-incorrectly-evaluates-i-pi-i-pi-1-to-zero}
\end{counterexamplebox}
