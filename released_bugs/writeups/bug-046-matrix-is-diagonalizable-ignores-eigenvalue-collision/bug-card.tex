\section*{Bug 46: Matrix.is\_diagonalizable Ignores Eigenvalue Collision}

\begin{counterexamplebox}
\textbf{Task.} Decide whether the symbolic matrix is diagonalizable.
\[
M=\begin{pmatrix}a&1\\0&b\end{pmatrix}.
\]

\medskip
\textbf{SymPy's answer.}
\[
\operatorname{is\_diagonalizable}(M)=\mathrm{True},\qquad
P=\begin{pmatrix}1&-1/(a-b)\\0&1\end{pmatrix}.
\]

\medskip
\textbf{Correct answer.} The answer is conditional: \(M\) is diagonalizable for \(a\ne b\), but it is not diagonalizable when \(a=b\).

\medskip
\textbf{Explanation.} Substituting \(b=a\) gives \(\begin{pmatrix}a&1\\0&a\end{pmatrix}\), a nontrivial Jordan block. Its only eigenspace is one-dimensional while the eigenvalue \(a\) has algebraic multiplicity \(2\), so an unconditional \(\mathrm{True}\) is wrong.

\medskip
\textbf{Likely root cause.} In \nolinkurl{sympy/matrices/eigen.py}, \SymPy{} trusts generic \texttt{eigenvects()} output and checks the symbolic eigenvalue keys \(a\) and \(b\) independently, without carrying the side condition \(a\ne b\) introduced by \(1/(a-b)\). This is a new instance of a known failure mode.

\medskip
\textbf{Artifact (GitHub).} \bugbundle{bug-046-matrix-is-diagonalizable-ignores-eigenvalue-collision}
\end{counterexamplebox}
