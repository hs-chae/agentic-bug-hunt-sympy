\section*{Bug 63: Fourier Transform Has Wrong Sign at Negative Frequencies}

\begin{counterexamplebox}
\textbf{Task.} Compute the Fourier transform, using \SymPy's convention
\(\int f(x)e^{-2\pi i x k}\,dx\), of
\[
\frac{\cos x}{x^2+1}.
\]

\medskip
\textbf{SymPy's answer.} At \(k=-1/3\), \SymPy returns
\[
\operatorname{fourier\_transform}\!\left(\frac{\cos x}{x^2+1},x,k\right)
\Big|_{k=-1/3}
\approx -0.596972407016359.
\]

\medskip
\textbf{Correct answer.} The correct transform is
\[
\frac{\pi}{2}\left(e^{-|2\pi k-1|}+e^{-|2\pi k+1|}\right),
\]
so at \(k=-1/3\) it is approximately \(0.596972407016359\).

\medskip
\textbf{Explanation.} Since
\(\cos x=(e^{ix}+e^{-ix})/2\) and
\(\mathcal{F}\{1/(x^2+1)\}(k)=\pi e^{-2\pi |k|}\), the shift theorem gives
the displayed positive, even transform. \SymPy's value at \(k=-1/3\) is the
negative of this value, so it is not an equivalent branch representation.

\medskip
\textbf{Likely root cause.} The diagnosis traces the bad sign to the Meijer
definite integration path in \texttt{sympy/integrals/meijerint.py}: half-line
Meijer formulas introduce branch-sensitive factors involving
\texttt{polar\_lift(k)**2}, \texttt{Abs(k)}, and a denominator \texttt{k},
which simplify to an erroneous \(\operatorname{Abs}(k)/k\) factor. This belongs
to a known meijerg Fourier-transform \(\operatorname{abs}/k\) sign family: open
issue \href{https://github.com/sympy/sympy/issues/25137}{sympy/sympy\#25137}
documents the same artifact under \texttt{real=True}, with a maintainer
root-cause comment matching this diagnosis; this integrand is plausibly a new
instance.

\medskip
\textbf{Artifact (GitHub).} \bugbundle{bug-063-fourier-transform-has-wrong-sign-at-negative-frequencies}
\end{counterexamplebox}
