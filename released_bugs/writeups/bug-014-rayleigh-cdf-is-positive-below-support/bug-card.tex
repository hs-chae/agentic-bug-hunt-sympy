\section*{Bug 14: Rayleigh CDF is positive below support}

\begin{counterexamplebox}
\textbf{Task.} Compute the CDF of a Rayleigh random variable below its support.
\[
R\sim\operatorname{Rayleigh}(1),\qquad F_R(-1)=\operatorname{cdf}(R)(-1)
\]

\medskip
\textbf{SymPy's answer.}
\[
\operatorname{cdf}(R)(-1)=1-e^{-1/2}.
\]

\medskip
\textbf{Correct answer.}
\[
\operatorname{cdf}(R)(-1)=0.
\]

\medskip
\textbf{Explanation.} A Rayleigh random variable has support \([0,\infty)\), so
the event \(R\leq -1\) is empty.  \SymPy{} is extending the nonnegative-branch
formula \(1-e^{-z^2/2}\) to \(z<0\), where the CDF should instead be zero.

\medskip
\textbf{Likely root cause.} The diagnosis points to
\nolinkurl{sympy/stats/crv_types.py}: \texttt{RayleighDistribution.\_cdf}
returns an unguarded formula even though the distribution declares support
\([0,\infty)\), and \nolinkurl{sympy/stats/crv.py} accepts that custom CDF
before generic support handling.  Deduplication frames this as a new failure
mode with no public precedent.

\medskip
\textbf{Artifact (GitHub).} \bugbundle{bug-014-rayleigh-cdf-is-positive-below-support}
\end{counterexamplebox}
