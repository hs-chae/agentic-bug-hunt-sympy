\section{Bug 14: Rayleigh CDF is positive below support}

\subsection{Minimal Reproducer}

\medskip

\begin{lstlisting}[style=bugpython]
from sympy.stats import P, Rayleigh, cdf

R = Rayleigh("R", 1)

print("cdf(R)(-1):", cdf(R)(-1))
print("P(R <= -1):", P(R <= -1))
print("expected cdf below support:", 0)
print("incorrect:", cdf(R)(-1) != 0)
\end{lstlisting}

\subsection{Observed Behavior}

\medskip

\begin{lstlisting}[style=bugpython]
cdf(R)(-1): 1 - exp(-1/2)
P(R <= -1): 0
expected cdf below support: 0
incorrect: True
\end{lstlisting}

The direct CDF call returns the positive expression \(1-\exp(-1/2)\) at a
negative argument.  This is inconsistent with the same distribution queried
through \(\operatorname{P}(R\leq -1)\), which correctly returns \(0\).

\subsection{Expected Behavior}

For a Rayleigh random variable \(R\) with scale parameter \(\sigma>0\),
\(\operatorname{cdf}(R)(z)\) should be \(0\) for every \(z<0\).  In the
representative case \(R=\operatorname{Rayleigh}(1)\), the mathematically correct
result is therefore
\[
  \operatorname{cdf}(R)(-1)=0.
\]

\subsection{Mathematical Explanation}

The Rayleigh distribution has support \([0,\infty)\).  Its density is
\[
  f_\sigma(x)=
  \begin{cases}
    \dfrac{x}{\sigma^2}\exp\!\left(-\dfrac{x^2}{2\sigma^2}\right), & x\geq 0,\\[0.8em]
    0, & x<0,
  \end{cases}
\]
so its CDF is the corresponding piecewise function
\[
  F_\sigma(z)=
  \begin{cases}
    0, & z<0,\\[0.4em]
    1-\exp\!\left(-\dfrac{z^2}{2\sigma^2}\right), & z\geq 0.
  \end{cases}
\]
The closed form \(1-\exp(-z^2/(2\sigma^2))\) is only the nonnegative branch of
the CDF.  Extending that branch to negative \(z\) is not an equivalent
representation: for \(z<0\), the event \(R\leq z\) is empty because no
Rayleigh-distributed value can be negative.  Thus the returned value is not a
harmless simplification, branch choice, or alternate form; it assigns positive
probability to a point below the distribution support.

\subsection{Source-Level Diagnosis}

The diagnosis identifies a support-guarding gap in the Rayleigh distribution's
custom CDF implementation.  In \nolinkurl{sympy/stats/crv_types.py},
\texttt{RayleighDistribution} declares the nonnegative support
\(\operatorname{Interval}(0,\infty)\), but its \texttt{\_cdf} method returns the
unguarded nonnegative-branch formula \(1-\exp(-x^2/(2\sigma^2))\).  The traced
call path then reaches \texttt{SingleContinuousDistribution.cdf} in
\nolinkurl{sympy/stats/crv.py}.  That method calls a distribution-specific
\texttt{\_cdf} first and returns it directly whenever it is not \texttt{None},
so the generic \texttt{compute\_cdf} path that would account for support is
bypassed.

\begin{lstlisting}[style=bugpython]
class RayleighDistribution(SingleContinuousDistribution):
    set = Interval(0, oo)

    def _cdf(self, x):
        sigma = self.sigma
        return 1 - exp(-(x**2/(2*sigma**2)))

def cdf(self, x, **kwargs):
    if len(kwargs) == 0:
        cdf = self._cdf(x)
        if cdf is not None:
            return cdf
    return self.compute_cdf(**kwargs)(x)
\end{lstlisting}

This source-level behavior explains the observed failure: for \(x=-1\), the
Rayleigh-specific \texttt{\_cdf} returns the algebraic expression
\(1-\exp(-1/2)\), and the caller accepts it before any support condition can
replace it by \(0\).  A plausible fix direction, supported by the diagnosis, is
to add the missing support guard to the Rayleigh CDF, for example by returning a
piecewise expression whose below-support branch is \(0\), or otherwise ensuring
that custom CDFs preserve the declared support.

\subsection{Additional Failing Instances}

The independent verification covers the representative case and five additional
instantiations with positive scale parameters and negative evaluation points.
In every row, \(z<0\), so \(R\leq z\) is an empty event for a Rayleigh random
variable.  The expected result is therefore \(0\) across the family, regardless
of the scale value.

\subsection{Related Issues Assessment}

The bug-finding harness performed a best-effort deduplication check and found a
\texttt{novel} verdict, which should be framed as a new failure mode with no
public precedent.  The only related public material identified in the artifact
is a discrete-support issue, SymPy issue \#20031, which is related in theme
because it concerns support handling, but it is not an exact duplicate of this
Rayleigh CDF failure.  The present bug remains individually actionable because
it gives a concise reproducible case, a concrete affected distribution method,
and a targeted regression test for the continuous Rayleigh CDF.

\subsection{Proposed SymPy Regression Test}

\medskip

\begin{lstlisting}[style=bugpython]
import pytest

from sympy import Rational, S, sqrt
from sympy.stats import Rayleigh, cdf


CASES = [
    (S.One, S.NegativeOne),
    (S(2), S.NegativeOne),
    (S.One, S(-2)),
    (S(3), S(-5)),
    (Rational(1, 2), S.NegativeOne),
    (sqrt(2), S(-3)),
]


@pytest.mark.parametrize("sigma,z", CASES)
def test_rayleigh_cdf_is_zero_below_support(sigma, z):
    R = Rayleigh("R", sigma)
    assert cdf(R)(z) == 0
\end{lstlisting}
