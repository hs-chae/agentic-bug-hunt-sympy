\section*{Bug 15: uniform quantile misses the \texorpdfstring{\(p=1\)}{p = 1} endpoint}

\begin{counterexamplebox}
\textbf{Task.} Compute the \(p=1\) quantile of a unit uniform random variable.
\[
U\sim\operatorname{Uniform}(0,1),\qquad Q(1)=\operatorname{quantile}(U)(1).
\]

\medskip
\textbf{SymPy's answer.}
\[
Q(1)=\varnothing.
\]

\medskip
\textbf{Correct answer.}
\[
Q(1)=1.
\]

\medskip
\textbf{Explanation.} The documented quantile definition is
\[
Q(p)=\inf\{x\in\mathbb{R}:p\leq F(x)\},
\]
where \(F\) is the cumulative distribution function.  For \(U\sim\operatorname{Uniform}(0,1)\), the CDF satisfies \(F(x)<1\) for \(x<1\) and \(F(1)=1\).  Thus \(Q(1)=1\).  SymPy's quantile API reports quantiles as sets, so the expected API-level result is \(\{1\}\); the alarming behavior is that it returns \(\varnothing\), meaning that no value is reported for this endpoint quantile.

\medskip
\textbf{Likely root cause.} The generic continuous quantile implementation in \nolinkurl{sympy/stats/crv.py} solves \(F(x)=p\) over the support; for \(\operatorname{Uniform}(0,1)\) this produces an inverse intersected with \texttt{Interval.Ropen(0, 1)}, so substituting \(p=1\) drops the endpoint.  Deduplication frames this as a new instance of a known failure mode.

\medskip
\textbf{Artifact (GitHub).} \bugbundle{bug-015-uniform-quantile-misses-the-p-1-endpoint}
\end{counterexamplebox}
