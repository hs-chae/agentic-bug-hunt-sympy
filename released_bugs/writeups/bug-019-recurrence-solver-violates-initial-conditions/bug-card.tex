\section*{Bug 19: recurrence solver violates initial conditions}

\begin{counterexamplebox}
\textbf{Task.} Solve the recurrence with the supplied initial conditions.
\[
 y(n+2)-(n+2)y(n+1)+y(n)=0,\qquad y(0)=y(1)=1 .
\]

\medskip
\textbf{SymPy's answer.}
SymPy's \texttt{rsolve} returns the zero sequence as the solution.
% \[
% \operatorname{rsolve}\bigl(y(n+2)-(n+2)y(n+1)+y(n),\,y(n),\,\{y(0):1,y(1):1\}\bigr)=0 .
% \]

\medskip
\textbf{Correct answer.} A valid answer must satisfy \(y(0)=1\) and
\(y(1)=1\), or the solver should report that it cannot produce such a solution;
the zero sequence is not a correct answer.

\medskip
\textbf{Explanation.} Substituting into SymPy's returned expression gives
\(0|_{n=0}=0\) and \(0|_{n=1}=0\), contradicting both supplied initial
conditions.  Forward recurrence from the requested values starts
\(1,1,1,2,7,33,\ldots\), so this is not an equivalent representation of the
requested initial-value solution.

\medskip
\textbf{Likely root cause.} The diagnosis locates the issue in
\nolinkurl{sympy/solvers/recurr.py}:\texttt{rsolve}: initial conditions are
applied only when the internal solution contains arbitrary constants.  Here
\texttt{rsolve\_hyper} returns the constant-free candidate \(0\) with no
symbols, so validation is skipped.  This is a new instance of a known failure mode.

\medskip
\textbf{Artifact (GitHub).} \bugbundle{bug-019-recurrence-solver-violates-initial-conditions}
\end{counterexamplebox}
