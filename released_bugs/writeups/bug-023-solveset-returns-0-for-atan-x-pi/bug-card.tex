\section*{Bug 23: solveset returns 0 for atan(x) = pi}

\begin{counterexamplebox}
\textbf{Task.} Solve the principal inverse-tangent equation over the complex domain.
\[
  \operatorname{solveset}(\operatorname{Eq}(\operatorname{atan}(x), \pi), x, \mathbb{C})
\]

\medskip
\textbf{SymPy's answer.}
\[
  \operatorname{solveset}(\operatorname{Eq}(\operatorname{atan}(x), \pi), x, \mathbb{C}) = \{0\}.
\]

\medskip
\textbf{Correct answer.}
\[
  \varnothing
\]

\medskip
\textbf{Explanation.} Substituting SymPy's returned value gives
\(\operatorname{atan}(0) - \pi = -\pi\), so \(0\) is not a solution.  The error
comes from treating \(\tan\) as a globally valid inverse of the principal branch
\(\operatorname{atan}\), even though \(\operatorname{atan}(\tan(\pi)) = 0\), not
\(\pi\).

\medskip
\textbf{Likely root cause.} The diagnosis points to
\(\texttt{sympy/solvers/solveset.py:\_invert\_complex}\), where the generic
inverse-function branch applies \(\texttt{atan(x).inverse() == tan}\) without a
principal-range condition and later checks only definedness.  This is a new
instance of a known failure mode.

\medskip
\textbf{Artifact (GitHub).} \bugbundle{bug-023-solveset-returns-0-for-atan-x-pi}
\end{counterexamplebox}
