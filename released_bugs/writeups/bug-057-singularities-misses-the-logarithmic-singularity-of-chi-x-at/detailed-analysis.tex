\section{Bug 57: missing Chi(x) logarithmic singularity at zero}

\subsection{Minimal Reproducer}

\medskip

\begin{lstlisting}[style=bugpython]
from sympy import Chi, S, singularities, symbols

x = symbols("x")
s = singularities(Chi(x), x, S.Complexes)

print("actual_singularities =", s)
print("expected_contains_zero =", s.contains(0))
print("Chi(0) =", Chi(0))
\end{lstlisting}

\subsection{Observed Behavior}

\medskip

\begin{lstlisting}[style=bugpython]
actual_singularities = EmptySet
expected_contains_zero = False
Chi(0) = zoo
\end{lstlisting}

On the recorded SymPy checkout, the full reproducer also reported
\texttt{right\_limit = -oo} and a high-precision numerical sample near
\(-45.47\) for \(\operatorname{Chi}(10^{-20})\). Thus \texttt{singularities}
reports that there are no complex singularities, even though SymPy's own
evaluation of \(\operatorname{Chi}(0)\) is complex infinity.

\subsection{Expected Behavior}

The result should contain \(0\). For the minimal case, an appropriate result is
\(\{0\}\), or any set representation whose membership test confirms
\[
0 \in \operatorname{singularities}(\operatorname{Chi}(x), x, \mathbb{C}).
\]

\subsection{Mathematical Explanation}

The hyperbolic cosine integral has the local expansion
\[
\operatorname{Chi}(x)
  = \gamma + \log(x)
    + \int_0^x \frac{\cosh(t)-1}{t}\,dt
\]
near \(x=0\), equivalently
\[
\operatorname{Chi}(x)
  = \gamma + \log(x)
    + \frac{x^2}{2\cdot 2!}
    + \frac{x^4}{4\cdot 4!}
    + \cdots .
\]
The series after the logarithm is analytic at the origin, but
\(\log(x)\) is singular there. Along the positive real axis,
\(\operatorname{Chi}(x)\to -\infty\) as \(x\to 0^+\), and in the complex
domain the logarithm gives a genuine logarithmic singularity at \(0\). This is
not a harmless alternative representation or branch convention: a singularity
set that is empty omits the point at which the function is not finite and at
which SymPy itself evaluates \(\operatorname{Chi}(0)\) to \(\texttt{zoo}\).

\subsection{Source-Level Diagnosis}

The diagnosis locates the relevant limitation in
\nolinkurl{sympy/calculus/singularities.py}, in the implementation of
\texttt{singularities} around lines 97--107. The traced public call path is the
direct call to \texttt{sympy.calculus.singularities.singularities}: the
expression is sympified, a small set of reciprocal trigonometric and hyperbolic
functions is rewritten, and then the routine scans only a few syntactic
patterns.

\begin{lstlisting}[style=bugpython]
for i in e.atoms(Pow): ...
for i in expression.atoms(log, asech, acsch): ...
for i in expression.atoms(atanh, acoth): ...
\end{lstlisting}

An unevaluated \(\operatorname{Chi}(x)\) expression has no \texttt{Pow},
\texttt{log}, \texttt{asech}, \texttt{acsch}, \texttt{atanh}, or \texttt{acoth}
atoms, so none of the scans adds \(0\) to the singularity set. The diagnosis
also notes that the missing information exists elsewhere in the SymPy source:
\(\operatorname{Chi}\) has \texttt{\_atzero = S.ComplexInfinity} in
\nolinkurl{sympy/functions/special/error_functions.py}, and its
\texttt{\_eval\_as\_leading\_term} method returns a leading term of the form
\(\log(x)+\texttt{EulerGamma}\) near zero. The current \texttt{singularities}
routine appears not to consult those function-level hooks, so the logarithmic
singularity remains invisible to its syntactic detector. A plausible fix
direction identified by the diagnosis is to add a special-function singularity
hook, or otherwise make \texttt{singularities} consult function-level
information such as values at candidate points or leading terms; for
\(\operatorname{Chi}(\mathrm{arg})\), roots of \(\mathrm{arg}\) should be
included as logarithmic singularities.

\subsection{Additional Failing Instances}

The independent verification checks the shifted family
\[
\operatorname{singularities}(\operatorname{Chi}(x-a), x, \mathbb{C})
\]
for \(a=0,1,2,3,4,5\). In every case, the expected singularity is the root of
the inner argument, \(x=a\), because the same local logarithmic behavior occurs
when \(x-a\to 0\). The verification also samples \(\operatorname{Chi}(\epsilon)\)
at high precision for a small positive \(\epsilon\), confirming the downward
divergence on the real approach to the singular point.

\subsection{Related Issues Assessment}

The bug-finding harness performed a best-effort deduplication check. The closest
public matches were \href{https://github.com/sympy/sympy/issues/18455}{sympy/sympy\#18455},
a broad plotting and singularity-detection discussion noting limitations for
non-rational functions, and
\href{https://github.com/sympy/sympy/issues/26208}{sympy/sympy\#26208}, which
concerns asymptotic series expansions for \(\operatorname{Shi}\) and
\(\operatorname{Chi}\) at infinity. The deduplication verdict is that this is a
new instance of a known failure mode: the general weakness for non-rational and
special-function singularities is known, but no exact public report was
identified for \(\operatorname{singularities}(\operatorname{Chi}(x),x,\mathbb{C})\)
returning \(\emptyset\) or for missing the \(\operatorname{Chi}\) singularity at
zero. The case remains individually actionable as a concrete regression test
and a specific special-function hook target.

\subsection{Proposed SymPy Regression Test}

\medskip

\begin{lstlisting}[style=bugpython]
import pytest

from sympy import Chi, S, singularities, symbols


@pytest.mark.parametrize("a", [0, 1, 2, 3, 4, 5])
def test_singularities_chi_includes_logarithmic_origin(a):
    x = symbols("x")
    result = singularities(Chi(x - a), x, S.Complexes)
    assert result.contains(S(a)) is S.true
\end{lstlisting}
