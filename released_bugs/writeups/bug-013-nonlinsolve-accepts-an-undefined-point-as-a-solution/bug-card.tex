\section*{Bug 13: nonlinsolve accepts an undefined point as a solution}

\begin{counterexamplebox}
\textbf{Task.} Solve the rational system with \SymPy's \texttt{nonlinsolve}.
\[
  \left\{\frac{xy-x}{x-1}-y=0,\quad y-1=0\right\}
\]

\medskip
\textbf{SymPy's answer.}
\[
  \operatorname{nonlinsolve}\!\left(\left[\frac{xy-x}{x-1}-y,\ y-1\right],[x,y]\right)
  = \{(1,1)\}.
\]

\medskip
\textbf{Correct answer.}
\[
  \varnothing
\]

\medskip
\textbf{Explanation.} Substituting \((1,1)\) makes the original denominator \(x-1\) equal to \(0\), so the first rational equation is undefined there.  Clearing the denominator yields the polynomial condition \(y-x=0\), but that step is valid only when \(x\ne1\); its apparent solution \((1,1)\) is therefore removed by the original domain restriction.

\medskip
\textbf{Likely root cause.} In \nolinkurl{sympy/solvers/solveset.py}, \texttt{nonlinsolve} records denominators before converting rational equations to numerators, but its no-remaining-equations polynomial success path returns \texttt{FiniteSet(*map(to\_tuple, poly\_sol))} before applying those denominator exclusions.  This is a new failure mode with no public precedent.

\medskip
\textbf{Artifact (GitHub).} \bugbundle{bug-013-nonlinsolve-accepts-an-undefined-point-as-a-solution}
\end{counterexamplebox}
