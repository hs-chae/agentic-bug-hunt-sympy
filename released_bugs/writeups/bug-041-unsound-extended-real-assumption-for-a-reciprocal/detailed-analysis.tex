\section{Bug 41: Unsound Extended-Real Assumption for a Reciprocal}

\subsection{Minimal Reproducer}

\medskip

\begin{lstlisting}[style=bugpython]
from sympy import symbols
from sympy.assumptions import Q, ask

xr = symbols("xr", real=True)
expr = 1/(xr - 1)

print("ask(Q.extended_real(expr)) =", ask(Q.extended_real(expr)))
print("expr.subs(xr, 1) =", expr.subs(xr, 1))
print("substituted value is_extended_real =", expr.subs(xr, 1).is_extended_real)
\end{lstlisting}

\subsection{Observed Behavior}

\medskip

\begin{lstlisting}[style=bugpython]
ask(Q.extended_real(expr)) = True
expr.subs(xr, 1) = zoo
substituted value is_extended_real = False
\end{lstlisting}

SymPy proves that \(1/(xr - 1)\) is extended real for an arbitrary real symbol
\(xr\).  This is unsound: \(xr=1\) is an allowed real substitution, and at that
point the expression evaluates to \(\mathrm{zoo}\), whose
\texttt{is\_extended\_real} property is \texttt{False}.

\subsection{Expected Behavior}

The query \texttt{ask(Q.extended\_real(1/(xr - 1)))} should not return
\texttt{True} under only the assumption that \(xr\) is real.  The correct result
is \texttt{False} or \texttt{None}; in either case, SymPy should not prove the
extended-real predicate without knowing that \(xr-1\neq 0\).

\subsection{Mathematical Explanation}

The extended real line consists of real values together with the signed
infinities \(-\infty\) and \(+\infty\).  It does not include complex infinity
\(\mathrm{zoo}\).  For
\[
  f(xr)=\frac{1}{xr-1},
\]
the denominator vanishes at the admissible real value \(xr=1\).  Therefore
\[
  f(1)=\frac{1}{0}=\mathrm{zoo},
  \qquad
  \mathrm{zoo}\notin \mathbb{R}\cup\{-\infty,+\infty\}.
\]
A universally valid assumptions conclusion for a real symbol must be compatible
with every substitution satisfying that symbol assumption.  Since the substitution
\(xr=1\) contradicts the claimed predicate, the result is not a harmless
simplification or merely an unknown singular point: it is a proof of a property
that the expression does not have over its full declared real domain.

\subsection{Source-Level Diagnosis}

The diagnosis locates the relevant rule in
\nolinkurl{sympy/assumptions/handlers/sets.py}, in the
extended-real predicate handler registered for \texttt{Add},
\texttt{Mul}, and \texttt{Pow}.  The traced public call asks the extended-real
predicate for \((xr-1)^{-1}\).  The expression is a
\texttt{Pow} whose arguments are \(xr-1\) and \(-1\).  The handler delegates to
\texttt{test\_closed\_group} in
\nolinkurl{sympy/assumptions/handlers/common.py}; that helper checks the
predicate on each argument and returns \texttt{True} when all arguments are
extended real.  The recorded trace confirms that the base \(xr-1\) is accepted
as extended real and then the whole reciprocal power is accepted:

\begin{lstlisting}[style=bugpython]
expr.args -> (xr - 1, -1)
ask(Q.extended_real(xr - 1)) -> True
ask(Q.extended_real((xr - 1)**-1)) -> True
\end{lstlisting}

The problematic rule is:

\begin{lstlisting}[style=bugpython]
@ExtendedRealPredicate.register_many(Add, Mul, Pow)
def _(expr, assumptions):
    return test_closed_group(expr, assumptions, Q.extended_real)
\end{lstlisting}

This closed-group reasoning is too broad for \texttt{Pow}.  In particular, a
negative exponent creates a reciprocal, and the reciprocal of an extended-real
quantity is extended real only when the base is known to be nonzero.  Here
\(xr-1\) is extended real but can be zero, so the handler proves the reciprocal
extended real while omitting the necessary side condition.  The diagnosis
suggests splitting \texttt{Pow} away from the simple \texttt{Add}/\texttt{Mul}
closed-group rule and requiring the base to be provably nonzero before returning
\texttt{True} for negative exponents or reciprocals; otherwise the handler should
return an unknown result.

\subsection{Additional Failing Instances}

The independent verification covers the same failure pattern for shifted simple
poles:
\[
  \frac{1}{xr-a}, \qquad a\in\{1,0,-1,2,3,-2\}.
\]
In every case \(xr\) is a real symbol, SymPy returns \texttt{True} for
\texttt{ask(Q.extended\_real(1/(xr - a)))}, and substituting the real value
\(xr=a\) gives \(\mathrm{zoo}\).  The expected behavior is therefore the same
across the family: without a proof that the denominator is nonzero, SymPy should
not prove the expression extended real.

\subsection{Related Issues Assessment}

The bug-finding harness performed a best-effort deduplication check.  The closest
public material identified was SymPy's assumptions predicate documentation for
\texttt{Q.extended\_real}, which confirms that the extended reals are real
numbers together with signed infinities, and documentation for the corresponding
\texttt{ExtendedRealPredicate} machinery.  No public issue was found for the
exact query \texttt{ask(Q.extended\_real(1/(xr - 1)))} returning \texttt{True},
nor for this specific reciprocal-with-possible-zero-denominator counterexample
with a symbolic base.  The same root-cause family is, however, publicly tracked:
the assumptions handlers unsoundly proving real-ness of a reciprocal with a
possibly-zero denominator.  This is recorded as issue
\href{https://github.com/sympy/sympy/issues/28150}{\#28150} (open) ---
\texttt{ask(Q.real(Pow(0, -1, evaluate=False)))} gives \texttt{True} --- with
fix attempts in PRs
\href{https://github.com/sympy/sympy/pull/28164}{\#28164} (closed) and
\href{https://github.com/sympy/sympy/pull/28377}{\#28377} (open).  The
deduplication verdict is therefore a known family with a specific new
manifestation rather than a wholly novel bug.  This \texttt{Q.extended\_real}
symbolic-base instance is nonetheless distinct and still unfixed: those PRs only
touch a concrete-number base through the \texttt{Q.real} number handler, and on
the current release \texttt{ask(Q.real(1/(xr - 1)))} already returns
\texttt{None} while only \texttt{Q.extended\_real} is wrongly \texttt{True}, so
they would not resolve it.  The report remains individually actionable because it
gives an exact counterexample, a traced handler location, and a focused
regression test.

\subsection{Proposed SymPy Regression Test}

\medskip

\begin{lstlisting}[style=bugpython]
import pytest
from sympy import zoo, symbols
from sympy.assumptions import Q, ask


@pytest.mark.parametrize("a", [1, 0, -1, 2, 3, -2])
def test_extended_real_reciprocal_requires_nonzero_denominator(a):
    xr = symbols("xr", real=True)
    expr = 1/(xr - a)
    assert ask(Q.extended_real(expr)) is not True
    assert expr.subs(xr, a) == zoo
\end{lstlisting}
