\section*{Bug 29: Negative branch returned for a principal fractional power}

\begin{counterexamplebox}
\textbf{Task.} Solve over the real domain:
\[
    x^{2/3}=4.
\]

\medskip
\textbf{SymPy's answer.}
\[
    \operatorname{solveset}(x^{2/3}=4,\ x,\ \mathbb{R})=\{-8,8\}.
\]

\medskip
\textbf{Correct answer.}
\[
    \{8\}.
\]

\medskip
\textbf{Explanation.} The returned value \(-8\) does not satisfy the original SymPy expression: under principal-power semantics,
\[
    (-8)^{2/3}=4(-1)^{2/3}=-2+2\sqrt{3}\,i \ne 4.
\]
The negative branch is valid for a real-root interpretation, but not for the principal \texttt{Pow} expression that was solved.

\medskip
\textbf{Likely root cause.} The diagnosis traces the result to \texttt{\_invert\_real} in \nolinkurl{sympy/solvers/solveset.py}, whose rational-power branch adds both \(y^{3/2}\) and \(-y^{3/2}\) for exponent \(2/3\). That inverts real-root semantics rather than principal \texttt{Pow} semantics, making this a new instance of a known failure mode.

\medskip
\textbf{Artifact (GitHub).} \bugbundle{bug-029-negative-branch-returned-for-a-principal-fractional-power}
\end{counterexamplebox}
