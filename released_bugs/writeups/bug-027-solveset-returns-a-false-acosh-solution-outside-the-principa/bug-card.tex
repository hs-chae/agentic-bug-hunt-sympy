\section*{Bug 27: solveset returns a false acosh solution outside the principal range}

\begin{counterexamplebox}
\textbf{Task.} Solve the principal inverse hyperbolic equation over the complex numbers.
\[
  \operatorname{acosh}(x)=2\pi i
\]

\medskip
\textbf{SymPy's answer.}
\[
  \operatorname{solveset}(\operatorname{acosh}(x)=2\pi i, x, \mathbb{C})=\{1\}.
\]

\medskip
\textbf{Correct answer.}
\[
  \varnothing
\]

\medskip
\textbf{Explanation.} Substituting SymPy's returned value gives
\(\operatorname{acosh}(1)=0\), so the residual is \(-2\pi i\).  The mistake is
that \(\cosh(2\pi i)=1\) solves only the composed equation after applying
\(\cosh\), not the original principal-branch equation.

\medskip
\textbf{Likely root cause.} In \nolinkurl{sympy/solvers/solveset.py},
the generic complex inversion path maps targets through
\(\operatorname{acosh}^{-1}=\cosh\) without checking the principal range of
\(\operatorname{acosh}\).  This is a new instance of a known failure mode.

\medskip
\textbf{Artifact (GitHub).} \bugbundle{bug-027-solveset-returns-a-false-acosh-solution-outside-the-principa}
\end{counterexamplebox}
